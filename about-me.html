How I Built Course Map

Not just a feature list — the actual problems I ran into and how I solved them.

Fixing bad data, not just displaying it

Several course links pointed to the wrong course entirely — a copy-paste artifact from the original dataset. I manually researched and verified each one against the real provider page instead of leaving broken links live.

Scroll performance with 100+ cards

A scroll-linked CSS animation was tracking every card's position continuously, causing visible lag. I replaced it with content-visibility and a one-time IntersectionObserver reveal instead.

Catching silent JS crashes before shipping

A leftover reference to a removed button was silently crashing the whole script on load — no courses, no filters, nothing. I built a small Node-based DOM simulator to actually execute the code and catch runtime errors before they reached a real browser.

Beyond a course list

Anyone can list courses. I added a ⌘K command palette, curated learning-path roadmaps that chain courses into a real sequence, and shareable filtered URLs — the kind of details that turn a listing into a product.

Installable, works offline

Added a manifest and a custom service worker so the app is installable and still works offline — no framework, no build step, just the fundamentals done properly.
